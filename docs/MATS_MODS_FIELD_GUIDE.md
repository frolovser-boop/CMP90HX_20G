## 1. Версии: чип → версия MODS (сводная по треду)

| Чип / карта | Рабочая версия | Примечания |
|---|---|---|
| **GA102 (3080/3090/3080Ti, CMP 90HX)** | **455.127–455.219** | Ошибки `bp @0x6c:464` на 3080Ti/3060Ti с 455.127 → брать 455.178+; для 3060Ti лучше **455.204–208.2**, не 219 |
| LHR 3060 (GA106) | 455.164–455.195 (219 даёт falcon/PMU HALTED) | `NVRM VBIOS invalid or rejected` 542, Device Id `_3YRG` — признак неподдерживающей версии |
| 3050 | 455.195/195.2 (127 даёт ложные read errors) | GA106 gold отсутствует во всех сборках |
| TU10x | 400.x (281.2) | 455 пишет «not the correct version for TU116»; 1650S → ≥400.250 |
| Pascal | 367 (или 370) | На 455 падает PMU GP102 |
| Ada 40xx | **520** (для 4070/4080 — 520.175+; 4090 — 520.112) | 520 образы **UEFI-only**; 520.132/520.175 — «UPDATES» (распаковывать поверх home) |
| Blackwell 50xx | **570.215+** (GDDR7) | NVMEMQUAL (внутренний NVIDIA stress) публично недоступен |

**Правило треда:** каждая новая версия MODS теряет поддержку старых чипов;
несоответствие версии карте проявляется на старте (`bp @0x6c:464`, Error 542,
`PMC_ENABLE ... doesnt exist`, Device Id `_XXXX`). Голд-файл — «ключ» чипа;
если gold отсутствует — `-no_gold` / `-old_gold`, но полные тесты MODS без голды
не идут (MATS работает).

## 2. MODS vs MATS: что чем тестировать

* ⚠️ **Для GDDR6X MATS неприменим как вердикт — он пропускает неисправности.**
  Основной инструмент для 90HX (GDDR6X) — **MODS** (тесты 178 / 94 / 3 / 2);
  MODS чувствительнее и находит сбои, которые MATS пропускает даже на 500–1000 МБ.
* **MATS ловит только грубое** (обрывы/КЗ) и на низких частотах; «MATS PASS» ≠
  исправность: кейсы — замыкание MLCC на рельсе VRAM прошло `-e 5`; утечка 19 В
  на 1.8 В «проходила» память. Полный тест — MODS с подъёмом частот памяти.
* **Объём теста:** дефолтные 10–20 МБ достаточны; 1 МБ может PASS (внутренняя
  память чипа ~1–3 МБ); **гонять весь объём бессмысленно** — на больших объёмах
  ошибки есть всегда (системные, а не чип).
* Стратегия madking: **MATS 10 МБ → MODS `-test 94` → тесты 144/143 → снова MATS**
  — «бывает, выдаёт по конкретной банке».
* Быстрый тест майнинговой карты: `./mats -3d_card -e 20`.

## 3. Рабочие командные строки (из треда)

```bash
# Основная рабочая строка для 3080/3090 (GA102, MODS 455):
./mods gputest.js -oqa -skip_rm_state_init -test 94 -fan_speed 70 \
    -dramclk_percent 100 -ignore_fatal_errors -run_on_error

# Побайтовый тест памяти (test 178):
./mods gputest.js -oqa -old_gold -run_on_error -ignore_fatal_errors \
    -dramclk_percent 110 -fan_speed 80 -test 178

# test 3 = MatsTest внутри MODS — ловит биты, которые 20МБ-MATS пропускает:
./mods gputest.js -oqa -test 3 -fan_speed 70

# Инициализация secondary GPU без теста (карта без видеовыходов / с iGPU):
./mods gputest.js -skip_rm_state_init -notest        # затем mats -3d_card -e 20

# Читать training status без прогона теста:
./mods gputest.js -skip_rm_state_init -notest

# Границы теста: пропустить первые N МБ (фреймбуфер монитора):
mats -b 16 -e 36          # или -no_scan_out при ошибках в первых МБ FB

# Дамп ВСЕХ сбойных адресов (огромный лог):
# добавить ключ -m -1

# Черный экран после теста при мониторе в карте: -disable_composition_mode
```
Тесты-ориентиры: **2** (pixel miscompares, стресс), **3** (MatsTest), **52**
(MarchTest), **94/95** (объём/производительность), **178** (побайтовый, GDDR6X
CMD-маппинг), **171** (InfoROM; Invalid InfoROM лечится `-testarg 171
SkipSerialNumCheck 1`), **264** (VkStressMesh, 570), **275** (память;
`020000275149 ... was skipped` = тест пропущен — версия/строка/VBIOS).
`-matsinfo` устарел (включён по умолчанию). Riser даёт MODS-ошибку шины
(Error 143, «1 линия вместо 16») — тестировать в слот напрямую.

## 4. Расшифровка результатов → физический чип

### NV_PFB_FBPA_x_TRAINING_STATUS (последняя цифра — код канала)
| Значение | Что значит |
|---|---|
| `0x00000000` | канал OK |
| `0x00000008` | **бит чип памяти** канала (субпартиция 1; напр. A1) |
| `0x00000002` | проблема **со стороны кристалла GPU**/контактов (субпартиция 0; напр. A0) |
| `0x0000000A` | оба банка канала (напр. весь канал F у 3090) |

Последние две цифры индекса = номер FBPA (FBPA_0→A … FBPA_5→F). Вариант
трактовки для 570.xx/GDDR7: «2»=банк 0 бит, «8»=банк 1 бит, «A»=оба банка.

### Read/Write errors по субпартициям (FBIO A0…F1)
* **Краткие FAILBITS (1–2 бита, напр. D061/D063) = конкретный чип**; линии D61/D63
  звонятся в сторону GPU — «чип искать со стороны ГПУ» (YunicheK); донорский чип
  чинил 3090.
* **Один битый чип часто даёт ошибки по всем каналам, но виновник выделяется
  бОльшим числом**; после замены той банки ошибки по всем каналам исчезают.
* **Отказ одной 16-бит половины чипа**: ~1 млн ошибок на один FBIO по битам
  D016–D031 (GDDR6 = два полунезависимых 16-бит банка; сбой портит целые
  32-бит слова блоками по 8–16 слов).
* **Ложное (не менять чипы!):** ровные 32/64/256 ошибки по всем субпартициям —
  фреймбуфер (мигающий курсор) и/или UEFI; повторный прогон чистый. Решение —
  iGPU + Legacy. **UEFI vs Legacy меняет набор FAILBITS** (D061+D063 в Legacy,
  только D061 в UEFI) — тестить в обоих, верить Legacy.
* ~1.3–2.9 млн ошибок, **все 384 бита во всех FBIO** = training не прошёл:
  шина/питание/GPU, не чипы.
* MODS при сильно битой памяти не инициализируется (NVRM timeouts, Error 603,
  отказ Falcon/ACR) — сам по себе диагностический признак.
* `Error 539 Generic falcon error` + PMU-RISCV HALTED при подъёме
  `-dramclk_percent` — зависание PMU (не память); на номинале тест проходит.
* Эталон здорового лога: PState 0, PCIe x16 (или x8 @8GT/s), NVVDD ~918 mV,
  ClkGpc ~1785 МГц, DRAM clock в норме профиля.

### Локализация GPU vs память (методика madking)
1. **Свапнуть два соседних чипа**: ошибки остались на том же FBPA → виновата
   сторона GPU (кристалл/пятаки), не память.
2. Прозвон пятаков до/после снятия памяти + **сверка NVMT-дампов до/после**.
3. Отлёт целого канала → чаще всего отвалившиеся пятаки под кристаллом.

## 5. Питание и плата (частые причины «памятных» симптомов)

* **GDDR6X требует VPP 1.8 В** — проверять первым делом (реальные отказы из-за
  отсутствия VPP); типовые сопротивления (Hynix S2C): 1.8 В ≈ 28.6 кОм,
  1.0 В ≈ 11 Ом, FBVDDQ ~30 Ом (занижено = КЗ линии); NVVDD ~0.2 Ом = КЗ кристалла.
* Пробитая шим FBVDDQ даёт `busVerifyBar2 garbage` + Error 541; после пробоя
  питания памяти контроллер обычно тоже убит.
* Стенды: рекомендованы ASUS/MSI на Intel (Z170/Z270/Z370/Z390, H81); Gigabyte
  «точно не подходит» (много фейлов загрузки); USB 2.0 порт; чипсет критичен
  (Z77 не завелась, Z590 — да; ASRock лечится перепрошивкой BIOS).
* Райзер: MODS видит 1 линию вместо 16 и ругается на шину — тестить в слоте.
* Карты без доп. питания: просадка 12 В под нагрузкой → глюки (райзер с 6-pin
  или подпайка 12 В перед токовым резистором).
* **Доп. питание карты обязательно** — иначе пустой report.txt.
* Пустой report.txt также: tiny смонтирована read-only; мёртвый GPU (в Windows
  код 18); зависший тест (mods.log гигантского размера — убрать MODS из commands).

## 6. Память GDDR6/GDDR6X: чипы и монтаж

* **Micron дата-коды**: всю память выпущенную **до 49-й недели 2018** менять
  целиком (коды вида 8T…); пригодны к использованию 8Y, 8Z, 9+ (таблица недель:
  A=2, B=4, …, X=48, Y=50, Z=52). Согласуется с листом levirepair (D9WCW 8\*\*77).
* **Правило замены чипа** (чарт NWR): тот же **бренд**, та же **ёмкость**,
  **скорость не ниже**. Сток 3080/90HX — Micron D8BGW (8 Гбит, 19 Gbps);
  16 Гбит GDDR6X Micron — **D8BZC (21 Gbps)** / D8BZF. ⚠️ D8BGX (21 Gbps, 3090)
  с дата-кодами OTT77 термочувствительны и часто уходят в КЗ; у GDDR6 «начиная
  с 8» (дата-код) известный дефект: проходит MATS с артефактами — менять все
  чипы. Hynix **S2C термочувствителен — реболлить свинцовыми шарами** перед
  использованием; H56G32CS4D X005 на 3060Ti проходит MATS с артефактами
  (иногда помогает снижение частоты). Чарт: [img/levirepair/nwr_mem_chart_1.jpg](img/levirepair/nwr_mem_chart_1.jpg).
* **⚠️ Смешивать Hynix и Micron (и партии) нельзя**: вендор памяти задаётся
  стропами, смешанные чипы работают на чужих тайминках → артефакты. Прямо
  относится к 20GB-модам.
* Замена Hynix → Micron/Samsung на 3060Ti-классе давала код 43 даже с подобранными
  стропами (контропыт) — планировать замену вендора с проверкой.
* **Снятие GDDR6X**: низом греть текстолит (~160°C), фен 330°C на чип до
  «плавания на шарах»; GPU: низ до 180°C, фен без насадки. Распиновка пятаков
  GDDR6X: vlab тред t=146059 (FBVDDQ — два канала + отдельная 1.8V VS_AON).
* **Охлаждение GDDR6X после мода**: термопрокладки >0.5 мм заменить на медную
  пластину (тоньше минимального зазора) + жидкий термопад; цель — температура
  памяти ~5°C от ядра под нагрузкой.

## 7. Прямой CMP-опыт в треде

* **CMP 90HX**: один безответный вопрос (стр. 22) — тема треда его не покрывает;
  наш проект закрывает GA102-диагностику через MODS 455 (см. DIAG_TOOLS).
* **CMP 50HX (TU106)**: после перепайки памяти на 2 ГБ чипы и страпов `00110` ПК
  перестал видеть карту — в таких случаях ищут папку **N30HMI** (есть в части
  сборок MODS, для карт не детектящихся после перепайки; см. YouTube saPvIIPP1cE).
  Наш аналог — CMP 40HX `FECS_PRI_FLOORSWEEP` / `FWSEC failed to halt` = карта
  не инициализируется (hardware floorsweep), 400.281.
* `./mats -3d_card -e 20` — базовый быстрый тест майнинговой карты.

## 9. Сводные правила для нашего 90HX-стенда

1. Основной вердикт по памяти — **MODS 455 (178/94/3), не MATS**.
2. Всегда тестировать **с iGPU** (видео не через тестируемую карту) и по
   возможности в **Legacy**; ровные 32/64 по всем каналам = ложное.
3. TRAINING_STATUS ≠ 0 → расшифровка по таблице §4; потом **свап соседних
   чипов** для GPU-vs-память.
4. VPP 1.8 В и FBVDDQ проверить раньше пайки.
5. Полный объём не гнать; для убедительности — повтор на `-dramclk_percent`
   100→105→110 (Hynix HC14 может не брать 119 — не делать выводов с разгона).
6. Смешивание вендоров памяти — запрет (стропы/тайминги) — критично для 20GB-мода.
