# CMP 50HX vs CMP 90HX — сравнение возможностей и решение о закупке

> Вопрос: при **одинаковой цене за карту** — есть ли смысл взять 2× CMP 50HX
> и модифицировать их, вместо 1× (или 2×) CMP 90HX?
>
> Все цифры — из верифицированных отчётов проектов `cmp50hx-unlock` (TU102)
> и `cmp90hx-unlock` (GA102), 2026. Помечены: 📏 замер, ≈ оценка.

---

## 1. Железо и потолок после анлока

| Параметр | CMP 50HX | CMP 90HX |
| :--- | :--- | :--- |
| Чип / архитектура | TU102, Turing (**sm_75**) | GA102, Ampere (**sm_86**) |
| SM / CUDA | 56 SM / 3584 | ~50–64 SM / до 8192 |
| Тензорные ядра | 2-е поколение: FP16, INT8, INT4 | 3-е поколение: FP16, **BF16, TF32**, INT8, INT4 |
| VRAM / шина | 10 ГБ GDDR6, 320 бит | 10 ГБ GDDR6X, 320 бит |
| Реальная ПСП 📏 | ~504–540 ГБ/с (OpenCL coalesced) | ~760 ГБ/с |
| FP32 после анлока 📏 | **13.5–14.9 TFLOPS** (было 0.43, +31.7×) | **~29.8 TFLOPS** |
| INT8 DP4A после анлока 📏 | **~48 TIOPS** (было 1.7, +28.4×) | INT8 Tensor ≈ 2× FP16 ≈ 230 TOPS ≈ |
| FP16 Tensor | ≈ 60–95 TFLOPS теорет. ≈ | **~115 TFLOPS 📏** |
| TDP | 180 Вт | 250–320 Вт |
| Профиль блокировки 📏 | FP32 ~1/32, DP4A ~1/28; FP16, INT32, ПСП — **не зажаты** | Issue-rate всех полей ~1/8 |

## 2. Зрелость модификаций (решающий фактор)

| Возможность | CMP 50HX | CMP 90HX |
| :--- | :--- | :--- |
| Compute unlock | ✅ **двумя путями**: UEFI one-click ( stock-драйвер, Linux **и Windows**) или патченный модуль 610.43.03 | ✅ rejoin15 (патченный модуль, Linux). UEFI — ⚠️ только план |
| PCIe Gen2 | ✅ **доказан** (patch 04 «all-feature», широта = слоту хоста; замер: x2 полоса хост-передач) | ✅ **подтверждён** (автор cmp90hx_pwner, [Habr ч.3](https://habr.com/ru/articles/1082724/): маски FEAT+XVE → FLR → retrain, 5 GT/s x16, CUDA DMA 6.4 GB/s) |
| CUDA P2P | ✅ **верифицирован**: 2×20 ГБ карты, `topo -p2p r/w = OK` (2026-10-06) | ⚠️ параметры есть, замера на 90HX нет |
| **20 ГБ мод** | ✅ **единственный проверенный в экосистеме**: 4 карты, готовый патч динамического WPR2, **GDDR6** (простая пайка, дешёвые чипы) | ⚠️ только теория; GDDR6X PAM4 паять заметно тяжелее, чипы дороже |
| ReBAR (BAR1 16/32 ГБ) | ✅ в составе all-feature пакета | ⚠️ упомянут, в стек не собран |
| Windows-анлок | ✅ готовый инсталлятор (UEFI + BYOVD Gen2 + `EnableGpuFirmware=1`) | ❌ нет |
| Фирменная диагностика памяти | ✅ MATS_400 (TU102 полный) + nvmt | ⚠️ через MODS 455.219 (`gldGA102.bin`, тест 275; платовых спеков PG132 нет) — [разбор](DIAG_TOOLS_MATS_NVMT.md) |

## 3. Архитектура и стек инференса — главное различие

| Аспект | CMP 50HX (sm_75) | CMP 90HX (sm_86) |
| :--- | :--- | :--- |
| BF16 / TF32 | ❌ нет (веса конвертировать в FP16) | ✅ нативно |
| FlashAttention-2 | ❌ (нужен sm_80+) → attention через xformers | ✅ |
| vLLM | Работает (cc 7.5), но V1-оптимизации/FA-бэкенды урезаны | ✅ полный (PagedAttention, continuous batching, FA2) |
| llama.cpp / GGUF | ✅ полностью (тензорные ядра задействуются) | ✅ полностью |
| ExLlamaV2 (EXL2) | ✅ поддерживает Turing | ✅ |
| Перспектива | PyTorch/CUDA пока держат sm_75, но закат ближе | sm_86 — долгая поддержка |

## 4. Производительность инференса

| Сценарий | 1× 50HX | 1× 90HX |
| :--- | :--- | :--- |
| Decode 12B Q4 (узкое место — ПСП) 📏/≈ | ~35–40 t/s (ПСП 0.68× от 90HX) | **55 t/s** |
| Prefill 12B Q4 | медленнее в ~1.5–2× (меньше Tensor TFLOPS, нет FA2) | 1770 t/s 📏 |
| Decode FP16 12B | ~35 t/s ≈ | ~55 t/s |

Многокарточные конфигурации (после анлока обеих карт):

| Конфигурация | VRAM | Что влезает | Скорость decode ≈ |
| :--- | :--- | :--- | :--- |
| **2× 50HX (сток 10 ГБ)** | 20 ГБ | 32B Q4 (Qwen2.5-32B AWQ) | ~30–40 t/s (PP) |
| **2× 50HX + 20GB мод ×2** | **40 ГБ** | **70B класс (Llama 3.3 70B Q4/Q5)** | ~12–20 t/s (PP, Gen2) |
| 1× 90HX (сток) | 10 ГБ | 8B Q8 / 12B Q4 | ~55 t/s (12B) |
| 1× 90HX + 20GB мод (не проверен) | 20 ГБ | 32B Q4 | ~40 t/s |
| 2× 90HX (цена ×2) | 20 ГБ | 32B Q4, TP=2 | ~40–50 t/s (TP) |

## 5. Ответ на вопрос: брать ли 2× CMP 50HX и модифицировать

### ✅ Да, имеет смысл — если цель «максимум модели за бюджет» и пайка не пугает:

1. **Уже из коробки** (без пайки): анлок зрелее, чем у 90HX (UEFI one-click на
   Linux и Windows), P2P и Gen2 — проверенные, а не гипотетические → 2×10 ГБ =
   20 ГБ = 32B-класс.
2. **20GB-мод — главный аргумент**: это **единственный проверенный** мод в
   экосистеме (4 карты, август 2026): готовый патч динамического WPR2 уже в
   драйвере, чипы **GDDR6 16Gb** (пайка проще, чем GDDR6X PAM4, чипы дешевле),
   фирменная диагностика (MATS/nvmt) полностью покрывает TU102. Итог —
   **2×20 ГБ = 40 ГБ → класс 70B**. За цену одной 90HX ни один 90HX-сценарий
   этого не даёт.
3. Энергетика и охлаждение мягче: 180 Вт на карту.

### ❌ Нет — если приоритеты другие:

1. **Скорость одной карты**: 90HX быстрее в decode ~1.4× и prefill ~1.5–2×.
2. **Современный стек**: BF16/TF32, FlashAttention-2, полный vLLM — только
   Ampere. Для продакшн-сервера с vLLM 90HX ощутимо удобнее.
3. **Минимум возни**: 90HX — одна карта, один слот, анлок rejoin15 одной
   командой; 2×50HX — два слота, 360 Вт, и мод = 2× паяльных работ
   (каждая с риском убить карту).
4. **Перспектива экосистемы**: sm_86 будет поддерживаться дольше, чем sm_75.

### Итоговая рекомендация

| Ваша цель | Выбор |
| :--- | :--- |
| Локальный сервер больших моделей (32B–70B), руки не боятся пайки, бюджет фиксирован | **2× 50HX** → анлок → 20GB-моды → 40 ГБ VRAM. Уникальное предложение при равной цене |
| Быстрый одиночный инференс 7–14B, современный стек, минимум возни, будущее за Ampere | **1× 90HX** |
| Максимальная скорость 32B при двойном бюджете | 2× 90HX + TP2/P2P (после проверки маски `0x88FE8`) |

### План внедрения для 2× 50HX (если выбран этот путь)

1. Анлок: one-click UEFI (Linux `.run` или Windows-инсталлятор) — стоковый драйвер остаётся.
2. Gen2 + ReBAR: all-feature пакет `cmp50hx-all-610.43.03` (одна сборка, всё включено).
3. P2P: патч уже в сборке cmp50hx-unlock; проверка `nvidia-smi topo -p2p r/w`.
4. 20GB-мод ×2 по [docs/20GB_PROCEDURE.md](20GB_PROCEDURE.md) (для TU102 шаги
   0–7 полностью применимы, включая фирменную диагностику MATS —
   этого пути нет у 90HX).
5. Инференс: llama.cpp `--split-mode layer` (PP) или vLLM TP=2/P2P;
   `stack/power.sh` → лимит ~150–180 Вт на карту.

## 6. Развилка «2×90HX vs 2×50HX + 2×20GB-мод» (при равной цене карты, 2026-11)

Ключевой факт экономики: **мод 90HX до 20 ГБ (GDDR6X D8BZC) дороже второй
карты**, поэтому сравнение сводится к «2×90HX без мода» против «2×50HX с модом».

| | **2× CMP 90HX (без мода)** | **2× CMP 50HX + 2× 20GB-мод** |
|---|---|---|
| Суммарно VRAM | 20 ГБ | **40 ГБ** |
| Доп. затраты сверх карт | конденсаторы 220 нФ ×2 (копейки) + работа | чипы 16 Гбит **GDDR6** ×20–24 + 2 реболлинга + страпы |
| Чипы для мода | (не нужны) | GDDR6 дешевле и доступнее GDDR6X: доноры **RTX 3060 12GB** (6 чипов 2 ГБ с карты), RX 6400/6500XT, PS5; Ali ~$8–12/шт |
| Мод проверен? | — | ✅ единственный проверенный (4 карты, 2026-08) + готовый патч WPR2 в сборке |
| Что запускается | 32B Q4 (2×10 ГБ) | **70B Q4/Q5**, 32B Q8, 8B с ctx 128k |
| Decode 12B Q4 | ~55 t/s (карта) | ~35–40 t/s (карта) |
| 70B Q4 (PP, Gen2) | — невозможно | ~12–20 t/s |
| Стек | Ampere: BF16/TF32, FA2, полный vLLM | Turing: llama.cpp/ExLlamaV2 отлично, vLLM урезан, нет BF16/FA2 |
| Мощность/тепло | 2×200–250 Вт | 2×180 Вт |

**Правило выбора:** если цель — **70B-класс или очень длинный контекст**,
2×90HX её не достигнет никогда (потолок плотности: 32 Гбит GDDR6X не существует —
MEMORY_MOD_20GB.md §2.1), и путь один: 2×50HX с модами. Если цель —
**максимальная скорость на моделях ≤32B** и современный стек — 2×90HX.

**Поэтапный вариант (снижает риск):** сначала **одна** 50HX + мод до 20 ГБ
(рецепт проверенный, чипы с донора RTX 3060 12GB) → проверить на своей станции →
вторая карта. 20 ГБ на одной карте уже дают 32B Q8 / 70B Q3; вторая добавляет
70B Q4/Q5. При этом 90HX-карта ничем не уступает в одиночной скорости —
можно комбинировать парк по задачам.
