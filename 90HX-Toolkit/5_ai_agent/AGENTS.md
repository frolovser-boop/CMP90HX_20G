# AGENTS.md — runbook для ИИ-агента (CMP 90HX на Ubuntu-сервере)

> Прочитай этот файл полностью перед выполнением работ. Ты (агент) подключаешься
> к серверу по SSH и выполняешь работы по настройке/диагностике карт CMP 90HX.
> Человеку на месте доступны: физический доступ, загрузочная флешка, кнопка reset.

## 1. Контекст

* Сервер: Ubuntu 20.04/22.04/24.04 или Debian 11/12, карты **NVIDIA CMP 90HX**
  (GA102, PCI `10de:220d`, 10 ГБ GDDR6X, видеовыходов НЕТ).
* Стек: compute unlock «rejoin15» на NVIDIA Open 610.43.03 (эксплойт V67 инлайн
  в инициализацию драйвера, персистентный). Анлок поднимает скорость выдачи
  инструкций Tensor/INT ядер в ~7-8× (prefill 224 → 1770 t/s).
* Инструменты на сервере (после bootstrap): `/opt/mycmp90/` — `stack/*.sh`,
  `tools/rm_issue_rate_query.py`, `cmp90hx-unlock/`, `logs/`.
* Полная документация: репозиторий `MyCMP90` (README, STATUS.md, docs/) —
  если скопирован на сервер: `/opt/mycmp90/docs/`.

## 2. Жёсткие правила безопасности

1. **Никогда** не прошивать VBIOS и не запускать пишущие команды nvmt
   (`dramtrain`, `ac`, `bgcal`, `char`) без явного подтверждения человека.
2. **Никогда** не выполнять `rm -rf` вне `/opt/mycmp90/logs`, `/tmp`.
3. Перезагрузка сервера — только после явного согласия человека (анлок
   персистентен, но человек может иметь незавершённые задачи).
4. Изменения power limit (`power.sh <Вт>`) разрешены в диапазоне 150–250 Вт;
   выход за диапазон — согласовать. Каждое действие фиксировать в отчёте.
5. Не устанавливать пакеты сверх списка bootstrap без необходимости; если нужно —
   объяснить зачем в отчёте.
6. Всё, что выполняется, логировать: `>> /opt/mycmp90/logs/agent-<дата>.log`.
7. Если команда вернула неожиданный результат — не повторять вслепую больше
   2 раз; описать состояние человеку (см. формат отчёта).

## 3. Подключение

```bash
ssh agent@<host>                       # sudo без пароля (bootstrap NOPASSWD)
ssh agent@<host> 'sudo /opt/mycmp90/agent-status.sh --save'   # быстрый статус
```
С Windows: ключ в `%USERPROFILE%\.ssh\id_ed25519`, конфиг в `~/.ssh/config`
(см. README.md рядом). Если sudo спрашивает пароль — bootstrap ставился с
`--no-nopasswd`; попросить человека ввести пароль интерактивно нельзя —
использовать `ssh -t` с человеком у клавиатуры.

## 4. Каталог команд (сервер)

| Команда | Что делает | Ожидаемый результат |
| :--- | :--- | :--- |
| `sudo /opt/mycmp90/agent-status.sh --save` | Полный статус (секции HOST/GPU/PCI/UNLOCK/THERMAL/P2P/TOOLS) | `UNLOCK: PASS` на настроенном сервере |
| `sudo /opt/mycmp90/stack/check.sh` | 9 полей Issue-Rate + PLM-маркеры | `PASS_CMP90HX_NINE_RATE_CHECK`; `DP=full FFMA=full FMLA16=full FMLA32=full IMLA0..4=full` |
| `sudo /opt/mycmp90/stack/install-unlock.sh` | Установка стека с нуля (10-20 мин сборка) | `UNLOCK: PASS` после; при первом запуске может потребовать перезагрузку (nouveau) → сообщить человеку, после ребута повторить |
| `LLAMA_MODEL=<path.gguf> /opt/mycmp90/stack/bench.sh` | pp512/tg16 + GEMM FP32/FP16 | Ориентиры: pp512 ≈ 1770 t/s (12B Q4), tg16 ≈ 55 t/s, FP16 GEMM ≈ 100-115 TFLOPS |
| `sudo /opt/mycmp90/stack/power.sh 200` | Power limit 200 Вт на все 90HX | `GPU N: power limit = 200 Вт` |
| `sudo /opt/mycmp90/stack/power.sh persist 200` | + systemd-юнит на загрузку | |
| `sudo /opt/mycmp90/stack/p2p-setup.sh` / `verify` | P2P для 2+ карт (настройка/проверка) | матрица `topo -p2p r/w` с `OK`; после setup — перезагрузка (согласовать) |
| `dmesg \| grep -iE "cmp90\|NVRM"` | Маркеры анлока/ошибок | `CMP90_PROD_STACK_SHIFT_PLM_V67: FEAT_PLM_after=0xffffffff` |

Интерпретация сбоев: `UNLOCK: FAIL` + пустые dmesg-маркеры → анлок не
выполнился в этой загрузке (модуль не тот/не загрузился) → проверить
`/lib/modules/$(uname -r)/updates/cmpunlocker*` и перезагрузку; **PCIe max
link 2.5GT/s — это нормально** (Gen2 достигается программно, см. STATUS.md и пункт «PCIe GEN2» в PWNER);
`INCONCLUSIVE` в check.sh — не считается провалом (таймаут RM-запроса).

## 5. Сценарии-прогоны

### A. Первичная настройка сервера
```bash
scp -r 90HX-Toolkit agent@<host>:/tmp/          # с Windows (человек или агент)
ssh agent@<host>
sudo bash /tmp/90HX-Toolkit/5_ai_agent/agent-bootstrap.sh
sudo /opt/mycmp90/stack/install-unlock.sh       # приnouveau-ребуте повторить
sudo /opt/mycmp90/stack/check.sh                # ожидание: PASS
sudo /opt/mycmp90/stack/power.sh persist 200
```
Отчёт: UNLOCK-статус, версии, power limit, ссылки на логи.

### B. Регулярная проверка (после ребута/обслуживания)
`agent-status.sh --save` → если `UNLOCK: FAIL` → `check.sh` → dmesg →
вывод человеку с гипотезой (по разделу 4).

### C. Бенчмарк A/B (до/после изменений)
`bench.sh` без модели (GEMM) + с `LLAMA_MODEL` (если человек указал путь).
Сохранять вывод `bench-*.log`, в отчёте — таблица до/после.

### D. Две карты: P2P + инференс
`p2p-setup.sh` (настройка) → **согласовать перезагрузку** → `verify` →
при `P2P: OK` можно запускать `run-vllm-tp2.sh` (первый запуск качает ~20 ГБ
весов — по Gen1 это долго; сообщить человеку). На Gen1 приоритет — PP
(layer-split), а не TP: обсуждать с человеком.

### E. Диагностика памяти (пайка/20GB-мод)
Серверно доступно только «мягкое»: `check.sh`, nvmt read-only (`nvmt p`,
`nvmt ts`), температуры `nvidia-smi`. Полная диагностика (MODS test 275,
FBPA-карты) — **off-line с загрузочной флешки** (папка `1_usb_diagnostics/`),
выполняет человек; задача агента — подготовить инструкцию и разобрать логи,
которые человек принесёт с флешки.

### F. VBIOS / 20GB-мод
Только планирование и разбор логов. Любые команды прошивки — под запретом
(правило 2.1). Чек-лист: `MyCMP90/docs/20GB_PROCEDURE.md`.

## 6. Формат отчёта человеку

```text

Статус: <OK / ТРЕБУЕТ ВНИМАНИЯ / БЛОКЕР>

Проблемы: <симптом → гипотеза → что предлагаю>

```

## 7. Известные грабли

* **nouveau**: первый запуск install-unlock при загруженном nouveau завершится
  просьбой перезагрузиться — это штатно; после ребута запустить снова.
* **Secure Boot**: если включён — модуль не загрузится; проверить
  `mokutil --sb-state`; решение — выключить в BIOS (человек).
* **Gen2 PCIe**: заявления «успешный Gen2» на 90HX не воспроизводятся
  стабильно; не считать его целью. Decode-фаза от шины не зависит.
* **P2P через bounce buffer**: если в verify скорость ~1.6-1.8 GB/s вместо
  ~6.7 GB/s — RegistryDwords не применились; проверить modprobe.d-файл.
* **check.sh без rm_issue_rate_query.py**: bootstrap кладёт его в
  `/opt/mycmp90/tools/`; при отсутствии — скачает сам (нужен интернет).
